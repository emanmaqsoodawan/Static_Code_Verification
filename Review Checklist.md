| :--- | :--- | :--- |
| **Initialization** | The average comes out completely wrong or behaves unpredictably because it adds numbers to whatever random garbage was sitting in memory. | In `averageAttack()`, the variable `double sum;` is declared but never initialized to `0.0` before adding values into it. |
| **Pointer** | Reading the label in `main` accesses expired stack memory, which causes garbage text or an instant crash. | `getMonsterLabel()` returns a reference (`std::string&`) to `label`, which is just a local temporary variable destroyed as soon as the function exits. |
| **Pointer** | Calling `attackMonster(99, 20)` instantly triggers a segmentation fault / crash. | `attackMonster()`, `getMonsterLabel()`, and `defeatMonster()` immediately dereference the pointer from `findMonster()` without checking if it returned `nullptr`. |
| **Pointer** | Accessing the name after freeing it leads to undefined behavior and potential data corruption. | In `defeatMonster()`, `m->name` is printed *after* calling `delete m;`, which is an illegal use-after-free. |
| **Pointer** | Memory is leaked on the heap and stays unfreed until the process terminates. | The bonus monster (`Monster* bonus = new Monster(...)`) in `main()` is created with `new` but has no matching `delete`. |
| **Pointer** | Mismatched array deallocation causes heap corruption and undefined runtime behavior. | In `readBoss()`, the name buffer is created using `new char[10]` but deleted with standard scalar `delete name;` instead of `delete[] name;`. |
| **Arrays** | Entering any name with 10 or more characters smashes the buffer and corrupts nearby memory. | In `readBoss()`, `std::cin >> name;` writes user input directly into a tiny 10-character raw array without any bounds limits. |
| **Arrays** | Adding the 6th monster (or the boss) writes past the allocated array, stomping over adjacent memory. | `spawnMonster()` writes directly into `monsters[monsterCount]` without verifying whether the array has already reached `MAX_MONSTERS` (size 5). |
| **Loops** | On the last loop pass, the program reads past the valid list and crashes when trying to access fields of an invalid pointer. | In `totalMonsterHealth()`, the loop runs while `i <= monsterCount` instead of `i < monsterCount`, causing an off-by-one out-of-bounds read. |
| **Arithmetic** | The check to catch fatal hits never runs, so monster health will wrap around into huge values instead of stopping at 0. | In `attackMonster()`, comparing `m->health - dmg < 0` implicitly casts the result to an `unsigned int`, which can mathematically never be less than zero. |
| **Arithmetic** | Any fractional damage gets completely cut off (for instance, 80 * 25 / 100 happens to be exact, but other numbers lose their decimals). | In `calculateDamage()`, all operands are integers, so integer division occurs before the result is turned into a `double`. |
| **Arithmetic** | If called on an empty monster list, the program crashes with a divide-by-zero exception. | `averageAttack()` divides `sum` by `monsterCount` without checking if `monsterCount` is zero. |
| **Control Flow** | It accidentally renames the first monster's ID, evaluates to true immediately, and always returns monster 0 instead of searching properly. | In `findMonster()`, the `if` statement accidentally uses assignment (`monsters[i]->id = id`) instead of the equality operator (`==`). |
| **Control Flow** | Calling `playerRank(50)` falls off the end of the function without returning anything, triggering undefined behavior. | In `playerRank()`, there is no `return` or fallback `else` branch for any score 100 or below. |
| **Functionalities** | The game still thinks the monster exists in the array; trying to access it later or shutting down the game will hit freed memory and cause a double free crash. | `defeatMonster()` deletes the object with `delete m;`, but never clears the pointer from `monsters[]` or decrements `monsterCount`. |
| **Classes** | Both game instances hold pointers to the exact same heap objects; when both destructors run at program exit, it causes a fatal double-free crash. | `Game` manages raw dynamic pointers with a custom destructor but breaks the Rule of Three by missing a copy constructor (`Game copy = game;` performs a shallow pointer copy). |
